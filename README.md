# Emulator PC Hub

[🇩🇪 Deutsch](README.de.md) · 🇬🇧 English

A controller-friendly Windows interface (C# / .NET 10 / WinUI 3) that brings together **the emulators you install
yourself** and **your own game dumps** in a console-style front end:

> Boot PC → Emulator PC Hub → pick a game → play → automatically back in the hub when you quit.

The hub is only the **shell / launcher**. It contains no games, ROMs, BIOS files, firmware, keys, emulators or mods
and **does not download any of these**. Everything that is played is provided by you (see
[What you have to provide yourself](#what-you-have-to-provide-yourself)).

## Features

**Interface & launching**
- Console Mode (borderless fullscreen) and desktop window, toggle with F11
- Fully controller-operable, own UI sounds (generated by the hub itself, no third-party audio files)
- Interface in **English and German**; choose a primary and a secondary language in the settings
- Start a game, hide the hub, wait for the game to end (including child processes), bring the hub back to the front
- Quit the running game with a button combo (hold Home + Minus for 1.5 s)
- Optional: start with Windows, shortcuts, direct game launch via `--launch <game ID>`
- Setup assistant on first start

**Library**
- Scans your game folders and recognizes titles from disc headers or title IDs
- Detects updates and DLC for a game and registers them in the emulator as external content (no NAND install needed)
- Favorites, recently played, filter per system, custom covers (cropping in the hub) – without a cover the hub
  generates its own tile from system color, monogram and title
- **Title and cover per language** (Wii U: titles read from the game data; otherwise your own entries) – the primary
  language is shown, otherwise the secondary language, otherwise the default
- Per-game settings and presets (e.g. “Vanilla” or a mod edition)

**Controllers**
- Automatic detection via SDL3 (Xbox, DualSense/DualShock, Pro Controller, Joy-Con, keyboard and more) including hotplug,
  battery level, rumble and players 1–4 (swappable)
- Controller profiles per game, button remapping, motion controls on suitable controllers
- At game start the hub writes the mapping directly into the configuration of the respective emulator
  (Dolphin, Cemu, Eden, melonDS, Azahar)
- Optional compatibility layer via PadForge (virtual Xbox controller), only when an emulator does not support a
  controller directly
- Support for original motion remotes via Bluetooth or DolphinBar

**Mods & presets**
- Per-game mod management: enable/disable mods, the hub switches them at launch to match the chosen edition
- Import your own mod packages (ZIP/folder), e.g. Retro Rewind or CTGP-DX
- Integration of Wheel Wizard and WiiCompiled (if installed by you)
- Manage Cemu graphic packs

**Profiles, avatars, saves, statistics**
- Hub profiles (e.g. “Player 1”, “Guest”) with avatar, preferred controller, their own favorites and statistics;
  selectable emulator users per profile (Cemu account, Eden user) → separate saves
- Avatar manager: import, export, rename and assign avatars from the emulator databases
  (only with your own emulator data; the hub ships no avatar graphics)
- Save manager: back up, restore, export/import and duplicate saves per game and profile;
  automatic snapshots before/after every game (max. 10 per game/profile)
- Statistics: playtime, sessions, starts, average/longest session, history (30 days / 12 weeks), by system, profile and preset

**Component management**
- Shows which emulators/tools are installed and checks paths and configuration
- Optional: query the current version number from the official project (version info only, **no download**)
- Installation and updates exclusively from **a file you downloaded yourself** (“Install from file …”);
  the package is checked first and existing configuration is backed up
- Portable installation under `integrations\` – nothing is written to system folders

**Other**
- Automatic backups (configuration, presets, mods, saves), log viewer, launch log (`Logs\launches.jsonl`)
- Portable layout: all data lives next to the hub (fallback `%LOCALAPPDATA%\EmulatorPCHub` if the folder is read-only)

## Supported components

All components are **independent third-party projects**. They are not included in the hub; you download them yourself
from the official site and install them in the hub under **Components → “Install from file …”**.

| Component | Type | Official site | Expected package |
|---|---|---|---|
| Dolphin | Emulator | https://dolphin-emu.org | Windows archive (ZIP/7z) with `Dolphin.exe` |
| Cemu | Emulator | https://cemu.info | Windows ZIP with `Cemu.exe` |
| Eden | Emulator | https://eden-emu.dev | Windows ZIP with `eden.exe` |
| melonDS | Emulator | https://melonds.kuribo64.net | Windows ZIP with `melonDS.exe` |
| Azahar | Emulator | https://azahar-emu.org | Windows ZIP with `azahar.exe` |

## What you have to provide yourself

The hub only works with content that **you own and created yourself**. None of it is bundled, offered or
downloaded automatically:

| Content | Used for | Note |
|---|---|---|
| **Game dumps** | all emulators | Only dumps of games you own and dumped yourself from your own hardware or discs |
| **Updates / DLC** | Eden (optional) | Dumped from your own console; the hub only registers them |
| **Keys** (e.g. `prod.keys`, `keys.txt`) | Eden, possibly Cemu | Extracted from your own console. Eden: copy to `integrations\switch\user\keys\` |
| **Firmware** | Eden | Dumped from your own console; install in Eden via *Tools → Install Firmware* |
| **System dumps / BIOS** (optional) | e.g. system menus or avatar editors in Dolphin/Cemu/Eden | Own dumps only; melonDS also runs with its free replacement BIOS |
| **Emulators, tools, mods** | see [Supported components](#supported-components) | Download yourself from the official project site |
| **Cover images** (optional) | Library | Your own images; without a cover the hub generates its own tiles |

> Downloading games, keys or firmware from the internet is not permitted in many countries.
> This project does not support piracy and gives no hints where such files can be found.

## Installation

1. Download the package `Emulator-PC-Hub-v1.1-win-x64.zip` from [Releases](../../releases).
2. Extract it to any **writable** folder, e.g. `D:\Emulator PC Hub\` (not to `C:\Program Files`, otherwise the hub
   falls back to `%LOCALAPPDATA%\EmulatorPCHub`).
3. Start `Emulator PC Hub.exe`.

On first start the hub creates the folders `data\`, `integrations\`, `Backups\` and `Logs\` next to itself.
Optionally you can create an empty file `EmulatorPCHub.root` in the root folder. Then the data lives there, even if
the EXE is in a subfolder (e.g. `App\`).

> The EXE is not signed. Windows SmartScreen may warn on first start (“More info → Run anyway”).

## Setup

The setup assistant walks you through these steps on first start. Later you can find everything individually in the hub.

1. **Choose game folders:** add folders with your own dumps (per system or mixed).
2. **Install emulators:** in the hub open **Components** → for an emulator click **“Official website”** →
   download the Windows version yourself → **“Install from file …”** and pick the downloaded file.
   Alternatively put the archive into `integrations\_downloads\`; the hub then offers it for installation directly.
3. **Your own keys and firmware** (Eden only): copy `prod.keys` to `integrations\switch\user\keys\`, install the
   firmware in Eden via *Tools → Install Firmware*.
4. **Controller:** connect a controller; the hub detects it automatically. Under *Controllers* you can swap players
   and create profiles.
5. **Import games:** the hub scans the folders and builds the library. Updates/DLC are matched automatically.
6. **Language (optional):** under *Settings → General → Language* choose primary and secondary language. Per game you
   can set title and cover per language under *All games → Settings*.
7. **Optional:** mods (mods page or game page → “Import from file/folder”), covers, autostart in Console Mode.

Then: pick a game → **Play**.

## Controls

| Key | Action |
|---|---|
| D-pad / stick / arrow keys | Navigate |
| A / Enter | Confirm |
| B / Esc | Back |
| X / Y | Quick actions (e.g. favorite, options) |
| Start / + | Settings |
| Home / Guide | Go to home screen |
| Home + Minus (hold 1.5 s) | Quit running game → back to the hub |
| F11 | Console Mode on/off |

**Command-line parameters**

| Parameter | Effect |
|---|---|
| `--console` | Start in Console Mode (fullscreen) |
| `--desktop` | Start in a window |
| `--launch <game ID>` | Launch a game directly (e.g. for shortcuts) |

The environment variable `EPCHUB_ROOT=<path>` sets the data folder.

## Network & privacy

- The hub **downloads no files**: no games, keys, firmware, emulators, tools or mods.
- On the *Components* page the hub only queries the **current version number and changelog** from the projects'
  official release feeds (GitHub API, dolphin-emu.org, git.eden-emu.dev, rwfc.net) so you can see whether an update
  exists. You download the update yourself.
- There is no telemetry, no accounts and no data transmission to the author.
- Third-party emulators and tools may have their own online features. Their settings and terms apply.

## Building from source

Requirements: Windows 10/11 x64, [.NET 10 SDK](https://dotnet.microsoft.com/download), PowerShell.

1. Clone the repository:
   ```powershell
   git clone https://github.com/mRbRaIn0/Emulator-PC-Hub.git
   cd Emulator-PC-Hub
   ```
2. **Provide SDL3 (for full controller support):** SDL3 is a third-party project and therefore not in the
   repository. Download the Windows x64 build from https://github.com/libsdl-org/SDL/releases (`SDL3-*-win32-x64.zip`)
   and put `SDL3.dll` (and optionally the license file as `SDL3-LICENSE.txt`) into
   `src\EmulatorPCHub.Controllers\native\`. Without SDL3 the hub still builds and starts, but then only uses XInput
   (Xbox-compatible controllers).
3. Build (runs the tests and publishes to `App\`):
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\build.ps1
   ```
   Result: `App\Emulator PC Hub.exe` (self-contained, including Windows App SDK). `-SkipTests` skips the tests.

NuGet dependencies (fetched via NuGet during the build): Microsoft.WindowsAppSDK, Microsoft.Data.Sqlite,
CommunityToolkit.Mvvm, and xUnit for the tests.
